# Fraud Detection Service

Сервис для скоринга мошеннических банковских транзакций в реальном времени. 
Проект демонстрирует полный цикл ML-разработки: от анализа данных до 
продакшен-готового API с тестами, CI/CD и мониторингом.

## Задача

Классификация транзакций на мошеннические/легитимные в условиях сильного 
дисбаланса классов (0.17% мошенничества). Решение оптимизировано под 
Precision-Recall, а не Accuracy, так как последняя неинформативна при 
таком дисбалансе (модель, всегда предсказывающая "не мошенничество", 
получила бы Accuracy 99.83%).

## Данные

[Credit Card Fraud Detection](https://www.kaggle.com/mlg-ulb/creditcardfraud) — 
284 807 транзакций европейских держателей карт за два дня, 492 из них 
мошеннические. Признаки `V1`-`V28` — результат PCA-преобразования исходных 
данных (анонимизация банком), `Time` и `Amount` — в исходном виде.

## Методология

### 1. Валидация
Стратифицированное разбиение train/test (80/20) — обычное случайное 
разбиение при таком дисбалансе рискует дать тестовую выборку с 
непредставительной долей мошенничества.

### 2. Метрики
Основная метрика — **PR-AUC** (Precision-Recall AUC), а не ROC-AUC: 
при сильном дисбалансе ROC-AUC завышает качество модели за счёт 
огромного количества True Negative. Порог классификации подобран 
осознанно по кривой Precision-Recall, а не используется по умолчанию (0.5).

### 3. Модель
LightGBM с `class_weight='balanced'`. Табличные данные с небольшим 
количеством признаков — классическая ниша для градиентного бустинга, 
нейросети здесь не дают преимущества и требуют больше ресурсов.

### 4. Подбор гиперпараметров
30 итераций Optuna с 5-кратной стратифицированной кросс-валидацией 
(вычислительно выполнено на Kaggle Notebooks). 

**Результат:** PR-AUC вырос с 0.8864 (baseline) до 0.8879 (tuned) — 
прирост +0.0015. Это показывает, что baseline уже близок к потолку 
качества, достижимого на этих признаках; дальнейший рост требует 
работы с данными (feature engineering), а не тюнинга модели. 
Все эксперименты залогированы в MLflow.

### 5. Итоговое качество (на отложенном test)

| Порог | Precision | Recall |
|---|---|---|
| 0.5 (по умолчанию) | 0.817 | 0.867 |
| 0.936 (подобранный) | 0.901 | 0.837 |

PR-AUC: **0.886**

## Мониторинг

`monitoring.py` строит отчёты о дрейфе данных через Evidently. 
Проверено на искусственно смещённом распределении `Amount` — 
инструмент корректно обнаруживает дрейф только в изменённом признаке 
(1 из 30), не давая ложных срабатываний на остальных.

## Запуск

### Обучение модели
```bash
uv sync
uv run python -m src.fraud_detection.train
```

### API локально
```bash
uv run uvicorn src.fraud_detection.api:app --reload
```
Документация: `http://127.0.0.1:8000/docs`

### Тесты
```bash
uv run pytest -v
```

### Docker
```bash
docker build -t fraud-detection .
docker run -p 8000:8000 fraud-detection
```

### Пример запроса

```bash
curl -X POST http://127.0.0.1:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"Time": 0.0, "V1": -1.36, ..., "Amount": 149.62}'
```

Ответ:
```json
{
  "fraud_probability": 0.0001,
  "is_fraud": false,
  "threshold_used": 0.9361
}
```
